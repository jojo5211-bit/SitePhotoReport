## 1. UI 示意與公開範例

GitHub README 的畫面圖片均為不含工程照片的 UI 示意圖，照片區使用「照片預覽」佔位內容，僅用來說明版面與操作位置：

- [Windows 桌面版工作區 UI](images/desktop-ui-mockup.svg)
- [Android 手機版欄位 UI](images/mobile-ui-mockup.svg)
- [Android PDF 預覽 UI](images/mobile-pdf-mockup.svg)

公開 repository 不包含使用者工程照片；實際使用時，照片只會存放在使用者自己的工程專案資料夾。

## 2. 這個作品解決什麼問題

工程現場通常需要把照片依施工項目、位置與階段整理成可交付的照片紀錄，例如施工前、施工中、施工後、改善前、改善後、材料進場與完工照片。照片數量一多，人工重新命名、分資料夾、排順序、補說明與排版非常耗時，也容易漏掉未分類照片。

SitePhoto Report 將這些工作集中在工程專案內：先建立工程項目與欄位，再匯入照片，透過拖放、批次操作或 AI 建議完成整理，最後輸出 PDF、Word 或 Excel。

核心原則：

1. 手動操作永遠可用，沒有 AI 也能完成整個報告。
2. AI 只提出建議或加速分類，人工修正優先且可以復原。
3. 原始照片不被覆蓋；旋轉、馬賽克、編號與輸出使用非破壞式資料或副本。
4. 工程資料和程式原始碼分離，公開 repository 不包含使用者照片、API Key 或工程專案。

## 3. 兩個版本的定位

| 版本 | 適合用途 | 主要功能 |
|---|---|---|
| Windows 桌面版 0.8.0 | 回公司整理大量照片與正式輸出 | 大量拖放、多選、欄位管理、AI 分類、照片編輯、PDF／Word／Excel |
| Android 手機版 1.1.2+13 | 工地現場拍攝、快速分類與預覽 | 拍照／匯入、即時加入、同步保存手機相簿、專案管理、快速分類、欄位排序、編號、PDF 預覽與分享 |

兩個版本都支援離線核心功能；使用外部視覺 API 時才需要網路。

## 4. Windows 桌面版操作

### 3.1 建立工程

1. 啟動程式，選擇「新增工程」。
2. 填寫工程名稱；工程編號、地點、業主、承包商、承辦人、日期、公司與工程說明可按需要填寫。
3. 選擇工程專案儲存位置。
4. 可套用已儲存的工程基本資料模板。
5. 建立後進入工作區。

未填寫的工程資料不會在 PDF／Word 封面產生「未填寫」文字或空白欄位。

### 3.2 建立項目與欄位

左側是工程項目清單，中間是照片欄位。項目與欄位都可：

- 新增、改名、刪除。
- 上移、下移或拖曳排序。
- 一次輸入最多 10 個名稱；空白行會略過。
- 使用單一欄位、施工前／中／後、改善前／後或自訂欄位。
- 欄位最右側的「＋」可一次新增多個欄位。
- 在欄位頁籤按右鍵可以刪除欄位；其中的照片會回到未分類，不會刪除原始檔。

建議先建立接近報告順序的項目，例如：現況、清潔、裂縫補強、底漆、防水層、面漆、完工。

### 3.3 匯入照片

支援 JPG、JPEG、PNG、WEBP 與 BMP。可使用「匯入照片」選檔或從 Windows 檔案總管一次拖曳照片到未分類區；程式會顯示載入進度並先建立縮圖，避免大量照片匯入時誤以為沒有反應。

匯入時會：

1. 保留原始檔案。
2. 以 SHA-256 檢查完全重複檔案。
3. 讀取 EXIF 拍攝時間、尺寸、方向與相機資訊。
4. 建立縮圖與預覽圖。
5. 將照片先放在未分類區。

### 3.4 手動分類與排序

- 單擊單選，Ctrl／Shift 支援多選。
- 將單張或多張照片拖到其他項目或欄位。
- 同欄位內拖曳可改變報告順序。
- Ctrl 拖曳或右鍵「複製到」可保留原位置並建立另一個 placement。
- Delete 或右鍵刪除只從工程移除 placement；原始照片仍保留在工程 originals 資料夾。
- 欄位內可右鍵選擇手動、拍攝時間早到晚／晚到早、檔名遞增／遞減。
- 報告順序是欄位由左至右、由上至下；拖曳時的紅色插入線代表實際插入位置。

未分類區另外顯示日期分隔線；沒有拍攝日期的照片依規則排在最後。

### 3.5 照片編輯

在右側照片屬性可以：

- 左轉 90°、右轉 90°、還原方向。
- 點擊預覽開啟全圖檢視；放大後可拖曳平移，縮小後恢復完整顯示。
- 開啟馬賽克編輯器，選擇筆刷塗抹、方形、圓形或手動描邊。
- 設定筆刷大小與輕／中／重模糊力度。
- 預設建立編輯副本並保留原版，也可以選擇套用馬賽克版。
- 設定照片說明、施工位置與是否加入報告。

編輯資料保存在工程的 edits 相關目錄；原始照片不會被改寫。

### 3.6 編號

在目前欄位的照片屬性執行「生成編號」，可選：

- 右上、左上、右下、左下。
- 數字顏色。
- 自訂像素大小。
- 透明底或色塊底。

編號只套用目前欄位，不會改變其他欄位。個別欄位可以「取消目前欄位編號」，不刪除照片、不改變照片順序。編號是報告渲染層，不會寫入原始照片。

### 3.7 AI 自動分類

先在工作區建立完整的項目與欄位，再到設定建立視覺 API 設定。按「自動分類」後，程式只會在既有項目／欄位中比對：

1. 讀取未分類照片與基本 metadata。
2. 將照片送給所選視覺模型，要求回傳候選項目、欄位、信心度與原因。
3. 達到門檻且能精確對應現有欄位的照片先放入建議位置。
4. 低信心、無法對應或分析失敗的照片留在未分類／待確認。
5. 使用者可接受、批次修改、退回未分類或手動拖曳。

AI 不會自行建立未知欄位，也不會覆蓋已經人工確認或移動的照片。外部 API 可能會接收工程照片，使用前請確認業主、監造與公司資料政策允許。

### 3.8 報告輸出

在報告設定中可以個別勾選 PDF、Word、Excel，也可以直接對單一格式按「預覽」或「輸出」。

PDF：

- 第一頁為工程基本資料封面。
- 支援黑白省墨版、清爽藍綠版、暖棕工程版。
- 每頁可選 1、2、4 或 6 張照片。
- 2 張上下排列；4 張 2×2；6 張 2×3。
- 照片依比例縮放並盡量填滿頁面，不拉伸。
- 每個項目／欄位可設定從新頁開始，避免標題留在上一頁、照片跑到下一頁。
- 可開關照片編號、拍攝時間、原始檔名、施工位置與說明。

Word：適合交付前再次編輯，會保留封面、標題、照片與說明。

Excel：定位為照片清冊，包含編號、項目、欄位、檔名、拍攝時間、位置、說明與縮圖。

輸出檔案會放在設定的固定輸出位置下，再建立工程專屬子資料夾。檔名重複時自動加上 `_1`、`_2`，不覆蓋舊檔；可設定輸出後自動開啟資料夾。

## 5. Android 手機版操作

### 4.1 現場流程

1. 首頁進入專案管理，新增或開啟工程。
2. 建立項目與欄位，長按或使用排序工具調整上下順序。
3. 在目前欄位拍照或從相簿一次匯入；直接拍攝的照片會同時保存到手機內建相簿。
4. 在未分類區快速分類，或點選照片後移到指定欄位。
5. 在欄位照片頁拖曳排序、生成編號或取消目前欄位編號。
6. 到 PDF 預覽檢查封面、章節、照片數與換頁。
7. 輸出後可開啟檔案、分享給指定對象，或交由手機上的 PDF 應用程式處理。

### 4.2 手機版與桌面版差異

手機版以現場快速輸入和預覽為主，桌面版以大量照片整理和正式 Word／Excel 輸出為主。工程資料欄位概念、照片編號、日期排序與 PDF 版型保持一致；若要在電腦接續整理，可透過專案備份資料移轉。

## 6. 設定與 API

桌面版設定包含：

- 預設工程位置。
- 固定報告輸出位置。
- 是否輸出照片時間戳。
- 是否輸出原始檔名。
- 輸出後是否自動開啟資料夾。
- 多組 OpenAI 相容 API 設定的新增、儲存、切換、刪除與測試接通。

視覺模型欄位應選擇支援圖片輸入的模型；模型名稱和 endpoint 依服務商文件填寫。程式不內建或公開任何 API Key。

## 7. 專案資料與備份

每個工程是獨立專案資料夾，通常包含：

```text
工程名稱.sprj/
├─ project.sqlite       # 工程資料、項目、欄位、排序與照片 placement
├─ project.json         # 專案摘要
├─ originals/           # 原始照片
├─ thumbnails/          # 快速列表縮圖
├─ previews/            # 預覽圖
├─ edits/               # 旋轉、馬賽克與報告衍生圖
├─ assets/              # Logo 與專案素材
├─ exports/             # 工程輸出報告
└─ backups/             # 備份
```

原始照片不存入 SQLite BLOB。刪除照片採軟刪除或移除 placement，避免誤刪原圖。備份工程時應將整個 `.sprj` 資料夾一起備份，不要只複製 PDF。

## 8. 常見問題

### AI 分類沒有移動照片

確認項目與欄位已建立、API endpoint 可連線、模型支援圖片輸入，並查看信心度與待確認區。AI 無法對應現有欄位時會刻意保留在未分類，這是避免照片消失的保護行為。

### 開啟舊工程很慢

舊工程第一次開啟可能需要重建缺失縮圖、讀取 EXIF 或掃描照片。完成後會使用縮圖和快取；工程照片數量很大時，建議分批匯入並定期備份。

### PDF 標題和照片分頁不直覺

使用最新版輸出模板，並啟用每個項目／欄位從新頁開始。照片超過單頁上限時才會使用續頁，續頁會保留項目／欄位名稱。

### 輸出檔案在哪裡

查看設定的固定輸出位置，程式會在其中建立工程名稱子資料夾。輸出完成後若開啟資料夾選項已啟用，會自動開啟該位置；若關閉，從報告輸出視窗顯示的完整路徑進入。

### 公開 repository 為什麼沒有 APK 或工程照片

這是刻意的安全邊界。GitHub repository 保存可重建的程式碼、文件、測試與建置腳本；APK 可由 Flutter 建置，工程照片與 API 設定屬於使用者資料，不應公開。
